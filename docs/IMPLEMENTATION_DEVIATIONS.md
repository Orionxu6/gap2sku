# Implementation Deviations (spec section 0 rule 19)

This document records differences between the spec and the implementation,
with evidence and handling.

## Deviation 1: AgentTeams v1.2.0 not installed in dev environment

- **Spec**: Phase 0 must verify AgentTeams v1.2.0 before binding.
- **Reality**: Dev environment has no `agt` CLI; AgentTeams not installed.
- **Handling**: Plan B dual-track delivery.
  - Domain Core (schemas, economics, graph, reviewer, replanning, pipeline)
    fully implemented and tested offline.
  - AgentTeams assets (Worker/Team CR YAML, manager-room messages, team_spec)
    generated and ready to apply once v1.2.0 is available.
  - `make demo-core` and `make test` run without AgentTeams.
  - `make demo-agentteams` emits Plan B messages for manual Element Web send.
- **Evidence**: `evidence/environment.txt` (generated by `make doctor`).

## Deviation 2: MCP transport uses HTTP JSON instead of full MCP SDK

- **Spec**: Use MCP Python SDK v1.x Streamable HTTP.
- **Reality**: `mcp` package not pre-installed; full MCP protocol server adds complexity.
- **Handling**: `mcp_server.py` uses Starlette HTTP JSON endpoints at the same
  URL paths (`/{role}/mcp`). Tool whitelist per role enforced server-side.
  Upgrade path: swap handler to `mcp` SDK FastMCP when available; endpoint
  URLs and tool contracts unchanged.

## Deviation 3: Live Data / Playwright / Brave / AgentLoop disabled

- **Spec**: P1 optional adapters.
- **Handling**: Feature flags in `.env.example` (all default 0/off).
  `LocalFixtureSource` is the only P0 data source. Interfaces reserved for
  `SafeFetchSource`, `BraveSearchSource`, `AmazonCustomerFeedbackAdapter`.

## Deviation 4: No real LLM calls in demo-core

- **Spec**: Workers use real LLM via AgentTeams.
- **Handling**: `make demo-core` runs fully deterministic offline (no LLM).
  This isolates domain logic from platform issues (spec 25: "demo-core is not
  final work, only separates platform from domain logic"). Final demo must
  run via AgentTeams with real LLM.
