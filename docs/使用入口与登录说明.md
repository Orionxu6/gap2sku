# Gap2SKU 使用入口与登录说明

这份说明只回答四件事：从哪里进入、什么时候登录、怎样切项目、怎样看后台。

## 1. 每天使用的三个网页

| 网页 | 地址 | 是否登录 | 用途 |
|---|---|---:|---|
| Decision Room | `http://127.0.0.1:8080/` | 不需要 | 日常主入口：看员工协作、冲突、结论、Artifact，并向 Agent 提交建议 |
| Product Story | `http://127.0.0.1:8080/story` | 不需要 | 查看最终产品方案；可切内部版、供应商 RFQ 版和评委版 |
| AgentTeams / Element | `http://127.0.0.1:18088/` | 会话失效时需要 | 后台排障：查看 Matrix 原始房间消息、员工是否在线和真实日志 |

日常只打开 Decision Room。Element 不是产品前台，也不是判断任务完成的依据；它只是后台日志入口。

## 2. 启动方式

第一次使用：

```bash
cd /Users/orionxu/Documents/gap2sku
make bootstrap
make configure-api
make model-preflight
make agentteams-install
make agentteams-apply
make local-up
```

以后日常启动：

```bash
cd /Users/orionxu/Documents/gap2sku
make local-up
make local-status
```

`make local-up` 会读取 `.env.local`，启动 Decision Room 和 MCP。AgentTeams Docker 容器通常保持运行；若 `make local-status` 显示容器未启动，再运行 `make agentteams-install`。

如果需要在终端前台观察 Workbench 日志，使用：

```bash
make workbench-live
```

## 3. 项目怎么切换

1. 打开 Decision Room。
2. 点击顶部中间的当前项目名称。
3. 在项目卡片中选择：
   - `午睡枕 · 美国站改款评估`：真实评论证据路径，预期 `REVISE`。
   - `桌边耳机与线材挂架 · 公开信号`：第二品类公开线索路径，预期 `REVISE`。
   - `桌边耳机与线材挂架 · 合成回归`：全合成流程回归，预期 `GO`，不能当成真实商业结论。
4. 切换后，员工协作流、目标约束、冲突、结论、Artifact 和 Product Story 链接会一起切换。

点击 `＋ 新建立项预览` 可查看三种入口：机会发现、已有概念验证、现有 SKU 改款。当前 v3 演示版把它作为立项预览，不会把未确认的草案直接推进为 GO。

## 4. 什么时候需要登录 Element

只有以下情况需要打开 Element：

- Decision Room 顶部显示 `REPLAY`，而你预期应为 `LIVE`。
- 某个 Worker 没有加入 Team Room 或没有发出 Handoff。
- 需要核对某条 Matrix 原始消息。
- 需要排查 AgentTeams 服务或房间权限。

登录用户名是本地 Matrix 管理员账号，当前配置默认显示为 `admin`。密码是执行 `make configure-api` 时由你本地设置或确认的 Matrix 管理员密码，不是 DeepSeek API Key，也不是 DashScope API Key。不要把密码或 API Key 发到聊天里。

## 5. 两个 API Key 分别做什么

- DeepSeek API Key：供七名 AgentTeams 文本 Worker 推理、协作、生成结构化 Handoff 和调用允许的 MCP 工具。
- DashScope API Key：只供 Prototype Designer 通过 `image.generate` 调用 Qwen Image 生成概念效果图和标注板。

没有 DashScope Key 时仍可完整跑离线流程，但使用固定回退图，并持续标记 `SYNTHETIC_CONCEPT`。概念图不是 CAD、结构证明、安全证据或样品确认。

## 6. 怎样确认当前真的跑通

依次执行：

```bash
make local-status
make agentteams-verify
make demo-agentteams
make check
make evidence
make verify-evidence
```

前台聊天只用于观察和提交建议。真正推进状态的依据是结构化事件、Artifact、规则、审批和绑定的 `spec_hash + policy_version`。

一次真实七员工联调可能需要十几分钟。`make demo-agentteams` 默认最多等待 20 分钟，并且只接受本轮 run_id 的七个新 Handoff；不要因为网页还显示上一轮 7/7 就提前判断本轮已经完成。

## 7. 停止本地网页

```bash
make local-down
```

该命令停止 Workbench 与 MCP，不删除数据库、证据、Agent 契约或 AgentTeams 房间历史。

## 8. Cloud Studio 中的入口

Cloud Studio 的端口预览分别开放 8080（Decision Room）、18088（Element）和 18090（MCP）。网页职责和本地完全相同；区别只是地址由 Cloud Studio 的端口转发域名提供。不要在云端继续访问本机的 `127.0.0.1` 链接。

上传 Cloud ZIP 后先执行 `make configure-api`，再执行 `bash scripts/cloud_deploy.sh`。只有生成且验证通过 `evidence/cloud-studio-e2e.json`，才能把云端状态称为完整跑通。
