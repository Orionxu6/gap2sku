# Gap2SKU 审核快照部署

这个部署包只展示已经生成的项目、Artifact、冲突、审计记录、Product Story 和历史协作事件。

## 运行边界

- 不启动 AgentTeams、Matrix 或 MCP。
- 不读取 `.env.local`，不需要 DeepSeek / DashScope API Key。
- 不接受消息、人工审批或新品输入写入。
- 老师关闭页面后再次访问，仍然看到同一批版本化结果。

## Railway 部署

1. 将仓库推送到 GitHub。
2. Railway 新建 Project，选择 GitHub Repo。
3. Railway 会使用根目录的 `railway.json` 和 `Dockerfile.review`。
4. 在 Service → Networking → Generate Domain 生成访问链接。
5. 用无痕窗口打开 `/`、`/story`、`/guide`，确认三个入口均可访问。

不需要添加 API Key、数据库 URL 或 Volume。审核快照所需的 SQLite 数据库和证据文件已随部署上下文打包；只读模式不会改变它们。

## 本地验证

```bash
make review-snapshot
```

然后打开 `http://127.0.0.1:8080/`。页面顶部应显示 `REVIEW SNAPSHOT`，发送框、人工审批和底层日志入口应隐藏。

## 提交审核链接

建议提交 Decision Room 根地址：

```text
https://<railway-domain>/
```

需要直接展示成果时使用：

```text
https://<railway-domain>/story
```
